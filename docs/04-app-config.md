# Конфигурация приложения с сервера

Требования — §9.2 `03_Nodus_iOS_Requirements.md`, контракт — `nodus_backend/docs/ios/10-app-config.md`.

## Как работает

- `AppConfigStore` (`Data/AppConfig/AppConfigStore.swift`) запрашивает публичный `GET /v1/app-config` без авторизации при каждом переходе в foreground (включая запуск, до анонимного входа) и не блокирует интерфейс.
- Последний ответ и `ETag` хранятся в app group (`appConfigBody`, `appConfigETag`); запрос идёт с `If-None-Match`, `304` — остаётся сохранённое. Офлайн при запуске сразу берётся сохранённое.
- `AppConfig` (`Data/AppConfig/AppConfig.swift`) разбирает ответ по ключам: нет ключа или неверный тип — значение по умолчанию, неизвестные ключи игнорируются.

## Ключи и значения по умолчанию

| Ключ | По умолчанию | Где используется |
|---|---|---|
| `links.privacy_policy` | `https://nodus.app/privacy` | экран согласия на AI, настройки |
| `links.terms` | `https://nodus.app/terms` | настройки |
| `links.support` | `mailto:support@nodus.app` | «Написать в поддержку» |
| `links.app_store` | нет | кнопка «Обновить»; без ссылки экран обновления без кнопки |
| `min_supported_version` | нет | версия ниже — `UpdateRequiredView` поверх всего приложения, обойти нельзя |
| `latest_version` | нет | версия ниже — toast «Доступна новая версия Nodus», не чаще раза в сутки |
| `limits.*` | 4000 / 200 000 / 30 000 / 60 | счётчики и проверки до отправки (диктовка, импорт, имя) |

Значения ссылок по умолчанию — предположение клиента: их нужно подтвердить или задать на сервере (`config set`).

Версии сравниваются по числовым компонентам (`AppVersion`: `1.10.0 > 1.9.0`, `1.2 == 1.2.0`).

## Тесты

`nodusTests/AppConfigTests.swift`: значения по умолчанию при неверных типах и мусоре, сравнение версий, блокировка только ниже минимума, `ETag`/`304`, офлайн.
