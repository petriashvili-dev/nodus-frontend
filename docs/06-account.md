# Аккаунт: email, восстановление, выход, удаление

Требования — §9 `03_Nodus_iOS_Requirements.md`, контракт — `nodus_backend/docs/ios/01-auth-and-account.md`.

## Где

«Настройки → Аккаунт» (`SettingsView.accountSection`):

| Элемент | Когда виден | Что делает |
|---|---|---|
| Аккаунт | всегда | email или «Анонимный» |
| Имя | всегда | `PATCH /me { display_name }` через Outbox при «Готово» и уходе с экрана; длина — `limits.display_name_max_chars` |
| Сохранить аккаунт | анонимный | `EmailCodeSheet(.link)`: `POST /auth/email/start` → код → `POST /auth/email/verify` → профиль; `UserId` и данные те же |
| Восстановить аккаунт | всегда, тихо (в onboarding не предлагается) | `EmailCodeSheet(.recover)`: предупреждение, что узлы текущего анонимного аккаунта не перенесутся; `POST /auth/email/sign-in/start` → код → `sign-in/verify` → токены |
| Политика, условия, поддержка | всегда | ссылки из app config |
| Выйти | есть email | системный alert → `POST /auth/logout`, `DELETE /devices/{installation_id}`, очистка |
| Удалить аккаунт | всегда | системный alert → `DELETE /me` (только онлайн, без Outbox) → очистка |

## Код из письма

- Ответ на `start` всегда одинаковый (не раскрывает, есть ли аккаунт).
- «Отправить код ещё раз» — через 60 с (сервер выдаёт не больше кода в минуту на адрес, лимит в час — 5).
- Ошибки: `invalid_code` — «Неверный или устаревший код», `email_already_linked` — «Этот email уже привязан к другому аккаунту — войди через «Восстановить аккаунт»», `validation_failed` — «Проверь адрес почты», `429` — «Слишком много попыток».

## Восстановление

1. Новые токены записываются в Keychain (`AuthSession.adopt`).
2. Локальные данные прежнего аккаунта стираются вместе с его Outbox (`SyncEngine.wipeLocalData(for:)`), уведомления снимаются; кеш помечается новым аккаунтом, чтобы ничего не загрузилось в него повторно.
3. `POST /devices`, профиль, затем snapshot нового аккаунта.

## Сессия

- Аккаунт с email, `401 invalid_refresh_token` → `SessionEndedView` («Сессия завершена» → «Войти» → восстановление). Локальные узлы остаются.
- Анонимный аккаунт → новый анонимный аккаунт, toast «Прежняя сессия потеряна. Узлы на этом устройстве сохранены»; узлы устройства загружаются в новый аккаунт следующим sync.

## Выход и удаление

После выхода или `204` (а также `401` — ответ на удаление потерялся, аккаунт уже удалён): Keychain очищается, локальная база и Outbox стираются, уведомления снимаются, доступ к AI сбрасывается. Следующее обращение к сети создаёт новый анонимный аккаунт. Без сети удаление не начинается: «Для удаления аккаунта нужна связь».

## App Review

Ревьюер входит через «Настройки → Аккаунт → Восстановить аккаунт» с email и фиксированным кодом из Sign-In Information (`EmailOtp:ReviewEmails` / `ReviewCode` на сервере). Для клиента это обычный вход — путь к пункту нужно описать в Review Notes.

## Тесты

- `AccountServiceTests`: привязка email, `invalid_code`, восстановление (токены, очистка под новый аккаунт), удаление (`204`, `401` после потерянного ответа, офлайн), имя через Outbox.
- `BackendIntegrationTests.savedAccountIsRestoredOnANewDevice` — против локального backend, запущенного с `EmailOtp__ReviewEmails__0=review@nodus.test` и `EmailOtp__ReviewCode=246810`; идёт около минуты из-за серверного ограничения «один код в минуту».
